# Chain-of-Thought Prompting 논문 분석 (Wei et al., 2022)

> *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models* — Jason Wei, Xuezhi Wang, Dale Schuurmans, Maarten Bosma, Brian Ichter, Fei Xia, Ed Chi, Quoc Le, Denny Zhou (Google Research, Brain Team), NeurIPS 2022, arXiv:2201.11903

CoT 프롬프팅을 처음 제안한 **원본 논문**이다. 평가 과제는 산술·상식·기호 추론이며, 텍스트 분류나 영업 메모 같은 비정형 데이터는 직접 다루지 않는다.
아래에서 **[논문]**은 논문 내용, **[추론]**은 실무에 맞춘 확장이다.
후속 연구는 [Auto-CoT 분석](../Zero-shot%20CoT%20Promting/README.md)을 참고.

## 1. 핵심 요약

**문제와 방법 (3문장)**
- LLM은 규모를 키워도 산술·상식·기호 추론처럼 여러 단계가 필요한 과제에서 성능이 잘 오르지 않았고(flat scaling curve), 기존 few-shot 프롬프팅도 이런 과제에서는 약했다.
- 이 논문은 few-shot 예시를 `<입력, 답>`이 아니라 **`<입력, 추론 과정(chain of thought), 답>`** 세 요소로 구성하는 CoT 프롬프팅을 제안한다. 모델 학습(파인튜닝) 없이 프롬프트만 바꾼다.
- 결과적으로 PaLM 540B에 예시 8개만 주고 GSM8K(수학 문장제)에서 정답률 18% → 57%로, 당시 파인튜닝 GPT-3 + 검증기의 최고 성능(55%)을 넘어섰다.

**Standard prompting과 CoT의 차이** (Figure 1)

| | Standard | CoT |
|---|---|---|
| 예시 | Q → A: "답은 11" | Q → A: "Roger는 처음 5개. 캔 2개 × 3개 = 6개. 5+6 = 11. 답은 11" |
| 모델 출력 | 답을 바로 생성 | 중간 추론을 먼저 쓰고 답을 생성 |

**왜 성능이 오르는가 (논문의 근거)**
- **[논문]** 복잡한 문제를 중간 단계로 분해해, 더 많은 단계가 필요한 문제에 더 많은 계산(토큰)을 쓸 수 있다.
- **[논문, 어블레이션]** 다음 세 가지 변형으로 원인을 분리했다(Figure 5).
  - 수식만 출력: GSM8K에서는 큰 효과가 없다. 자연어 추론 없이는 문제 의미를 수식으로 바로 옮기기 어렵다.
  - 점(...)으로 토큰 수만 늘리기: 기준선과 비슷하다. 계산량(길이)만으로는 효과가 없다.
  - 답을 먼저 쓰고 추론을 뒤에 붙이기: 기준선과 비슷하다. 답 앞에 놓인 순차적 추론이 실제로 쓰여야 한다.
- **[논문]** 쉬운 문제(한 단계짜리 SingleOp)에서는 개선이 없거나 미미하다. 복잡한 문제일수록 이득이 크다.
- **[논문, 주의]** 대형 모델에서만 효과가 난다. 소형 모델은 "유창하지만 비논리적인" 추론을 만들어 오히려 나빠진다(LaMDA 420M GSM8K 2.6 → 0.4, 2B 3.6 → 1.9).
- **[논문, 주의]** 상식 과제 CSQA에서는 이득이 미미했다. GPT-3 175B는 오히려 79.5(standard) → 73.5(CoT)로 내려갔다.

## 2. 핵심 개념 3가지

### ① `<입력, 추론, 출력>` 트리플 (CoT 프롬프트의 구조)
- 개념: 정답만 보여주던 few-shot 예시에 사람이 푸는 방식의 중간 단계를 추가한다.
- 구조: `[Q1, 추론1, A1] [Q2, 추론2, A2] … [Q_test] → 모델이 추론을 생성 → 답`
- 예: "Sammy가 사람이 많은 곳에 가려 한다. 어디로 갈까?" → "답은 사람이 많은 곳이어야 한다. 경마장·사막·아파트·검문소는 아니고 인구 밀집 지역이 맞다. 답은 (b)" (Figure 3, CSQA)
- 논문의 장점 4가지: 문제 분해, **해석 가능성**(어디서 틀렸는지 디버깅 가능), 산술·상식·기호 등 언어로 풀 수 있는 과제에 범용, 기성 LLM에 예시만 넣으면 유도 가능.

### ② 창발적 능력 (Emergent Ability of Scale)
- 개념: CoT는 모델이 약 100B 파라미터 수준에 도달해야 효과가 난다.
- 구조: `소형 모델 + CoT = 유창하지만 틀린 추론 → 성능 하락`, `대형 모델 + CoT = 성능 급상승`
- 예: GSM8K에서 PaLM은 8B, 62B, 540B로 커질수록 CoT의 이득이 커지고, standard prompting은 완만하게만 오른다(Figure 4).
- 실무 시사점: "CoT를 넣으면 무조건 좋아진다"가 아니라 **모델 크기에 따라 결과가 갈린다**.

### ③ 예시 작성자와 스타일에 견고하다 (Robustness)
- 개념: 예시를 쓴 사람이나 문체가 달라도 standard prompting보다 크게 좋다. 다만 작성자 간 편차는 존재한다.
- 검증: 공저자 3명이 각자 쓴 CoT, 더 간결한 스타일, GSM8K 학습 데이터에서 무작위로 뽑은 예시, 예시 순서·개수 변경(Figure 6)
- 예: LaMDA 137B에서 어떤 작성자의 CoT를 써도 GSM8K·MAWPS에서 standard를 크게 상회했다.
- 의미: 정교한 프롬프트 엔지니어링 없이도 효과가 있다. 다만 예시 작성 노력이 성능 편차를 만들 수 있다는 점은 Auto-CoT 연구의 출발점이 된다.

## 3. 실무 적용: 영업 메모 → 광고주 상태 분류

**[추론]** 논문의 트리플 구조를 분류 과제로 옮기면 `<영업 메모, 판단 근거, 상태 라벨>`이 된다.

### 프롬프트 구조 (Few-shot CoT 예시)

```
[System]
당신은 광고 플랫폼의 광고주 케어 분석가입니다.
영업 메모를 읽고 광고주 상태(유지/확장/위험/불만)를 분류하세요.
판단 근거를 먼저 단계별로 쓰고, 마지막 줄에 "So the answer is: <라벨>"로 끝내세요.

[Few-shot 예시 (사람이 직접 작성한 트리플)]
메모: "이번 달 예산은 검토 중이라고 하심. 성과 얘기는 없었음."
근거: 예산을 검토 중이라는 사실만 확인된다. 증액·감액 여부가 명시되지 않았다.
      불만 표현이 없으므로 '불만'은 아니다. 감액 가능성이 남아 있어 '유지'로 단정하기 어렵다.
      So the answer is: 위험 (확신도 낮음)

메모: "다음 분기에 신규 상품도 같이 집행해 보고 싶다고 먼저 연락 옴."
근거: 광고주가 먼저 신규 상품 집행 의사를 밝혔다. 이는 예산 증가 신호다.
      So the answer is: 확장

[Test]
메모: "{실제 메모}"
근거:
```

**설계 포인트**
- 논문처럼 예시는 4~8개 정도, **추론 → 최종 답의 순서**를 유지한다. 답을 먼저 쓰고 근거를 뒤에 붙이면 효과가 사라진다(어블레이션).
- 마지막 줄에 정해진 형식("So the answer is: …")으로 답을 끝내도록 해 파싱을 쉽게 만든다.
- 근거가 **해석 가능한 창**이 되므로, 분류가 틀렸을 때 어느 단계에서 어긋났는지 확인하고 프롬프트를 개선할 수 있다.

## 4. DA·DX/AX 관점의 한계와 고려사항

논문이 직접 언급한 한계와, 여기서 확장한 **[추론]**을 구분해 정리한다.

| 항목 | 논문에서 알 수 있는 것 | 실무 대응 |
|---|---|---|
| **추론의 진위** | CoT가 인간의 사고를 모방하지만 모델이 실제로 "추론"하는지는 열린 문제다. 정답인데 추론이 틀린 사례도 있다(GSM8K 정답 50건 중 2건). | 근거를 맹신하지 말고, 라벨 정확도와 근거 적합성을 별도로 평가한다. |
| **환각** | 추론 경로의 정확성은 보장되지 않으며, 오답 50건 분석에서 46%는 사소한 실수, 54%는 의미 이해·일관성의 큰 오류였다. | 근거 문장에 메모의 원문 인용을 강제하고 실제 존재 여부를 검증한다. 불확실하면 사람 검토로 넘긴다. |
| **비용·서빙** | 큰 모델에서만 CoT가 작동해 실서비스에서 비용이 크다고 저자들이 명시했다. | **[추론]** 토큰이 길어지는 비용 증가를 실측하고, 쉬운 메모는 CoT 없이 처리하도록 분기한다. |
| **지연시간** | 논문에 측정값 없음. | **[추론]** 출력이 길어지는 만큼 느려진다. 실시간이 필요 없으면 배치로 처리한다. |
| **분류 과제 적합성** | 산술·기호에서 큰 이득, 상식(CSQA)은 미미하거나 오히려 하락(GPT-3 79.5 → 73.5). | 분류에서는 CoT 이득이 보장되지 않는다. |
| **주석 비용** | 예시 작성 비용은 few-shot에서는 작지만 파인튜닝에서는 부담이 될 수 있다. | 예시를 자동으로 만드는 방법은 [Auto-CoT 분석](../Zero-shot%20CoT%20Promting/README.md) 참고. |

### 반드시 해야 할 검증
- 같은 라벨셋으로 **Few-shot(추론 없음) vs Few-shot CoT를 A/B 비교**한다. 정확도가 비슷하면 더 싸고 빠른 쪽을 쓴다.
- "위험" 클래스의 **재현율(recall)**과 오탐으로 인한 CS 부담을 함께 평가한다.
- 논문 실험은 2022년 기준 모델(GPT-3, LaMDA, PaLM, UL2, Codex)이다. 최신 모델은 CoT 없이도 강하거나 내부적으로 추론하는 경우가 많아 절대 수치를 그대로 기대하면 안 된다.
- 영업 메모에는 고객사 정보가 있으므로 외부 API 전송 전 마스킹과 보안 정책을 확인한다.

## 아티클 구성 제안
1. 도입: 모델을 키워도 안 오르던 추론 과제와 few-shot의 한계
2. 트리플 구조(개념 ①)와 어블레이션(추론이 왜 도움이 되는가)
3. "소형 모델에서는 오히려 나빠진다"(개념 ②)와 분류 과제(CSQA)에서의 함정
4. 영업 메모 분류 프롬프트 설계와 A/B 검증 결과
